# 回归规则库（Rules）

> 目的：把页面级 TC 的重复步骤沉淀为可复用判断规则。  
> 使用方式：先看改动类型，再按 `RULE-XXX` 触发回归，不再逐条维护页面 TC。

## 底线规则（所有改动默认检查）

### RULE-001：可达（Reachability）
- 适用类型：`page / create / drawer / footer / regression`
- 触发条件：改动了导航入口、路由参数、菜单结构、页面挂载关系。
- 检查方法：从真实入口进入目标页面或弹层，能稳定到达且落在正确上下文（L1/L2/target）。
- 常见反模式：
  - 入口可点击但落到错误目标或空白页。
  - 仅手输 URL 可达，UI 链路不可达。

### RULE-002：可用（Usability）
- 适用类型：`page / create / drawer / footer / regression`
- 触发条件：改动了核心交互（创建、双击、切换、提交、关闭）。
- 检查方法：核心操作触发后有明确状态变化，且下一状态可继续操作。
- 常见反模式：
  - 按钮有响应但业务状态不变化。
  - UI 显示切换了，数据或上下文未切换。

### RULE-003：可回退（Recoverability）
- 适用类型：`page / create / drawer / footer / regression`
- 触发条件：新增或修改了详情态、创建态、弹层态、抽屉态、Tab 态。
- 检查方法：从任一深入态都能回到上一级稳定态（列表/原页面），且上下文不丢失。
- 常见反模式：
  - 只有进入链路，没有返回链路。
  - 返回后落在错误 L1/L2 或错误记录。

### RULE-004：无阻断（Non-Blocking）
- 适用类型：`page / create / drawer / footer / regression`
- 触发条件：任意前端状态、渲染、路由、数据绑定改动。
- 检查方法：主链路执行过程中不出现白屏、崩溃、死循环跳转、不可恢复报错。
- 常见反模式：
  - 异常吞掉后页面卡死，无提示。
  - 局部错误导致全局交互不可继续。

## 类型化风险规则

### RULE-101：列表到详情链路完整
- 适用类型：`page / footer`
- 触发条件：改动列表行交互、详情渲染器、主从布局、双击行为。
- 检查方法：列表可见且可选中，进入详情后内容对应当前项，并可回到列表。
- 常见反模式：
  - 列表可见但无法进入详情。
  - 详情显示上一次记录，未随当前行更新。

### RULE-102：创建入口与取消返回一致
- 适用类型：`page / create / footer`
- 触发条件：改动创建入口、创建态容器、取消逻辑、返回按钮。
- 检查方法：创建入口可进入创建态，取消后回到原列表/原弹层态且无残留状态。
- 常见反模式：
  - 取消后仍停留在半创建态。
  - 返回到了错误模块或错误选项卡。

### RULE-103：详情与列表上下文一致
- 适用类型：`page / footer / drawer`
- 触发条件：改动主从页、右侧详情区、列表筛选与选中态。
- 检查方法：详情标题/字段与列表当前选中项一致，收起或返回后列表上下文保持。
- 常见反模式：
  - 详情内容与选中项错位。
  - 返回后列表重置到意外状态且无法定位刚操作项。

### RULE-201：Create 默认值策略可验证
- 适用类型：`create / page / footer`
- 触发条件：改动默认值、初始表单状态、字段联动初始化。
- 检查方法：进入创建态时默认值与设计一致，动态默认值（如年份）在当前上下文正确生效。
- 常见反模式：
  - 默认值缺失或沿用旧状态污染新建数据。
  - 显示默认值与实际提交值不一致。

### RULE-202：Create 必填与校验门禁生效
- 适用类型：`create / page / footer`
- 触发条件：改动必填规则、前端校验、字段依赖、提交按钮可用条件。
- 检查方法：缺失必填或非法输入时必须阻止提交，并给出可见校验提示。
- 常见反模式：
  - 必填未填仍可提交。
  - 仅高亮字段但没有明确错误提示或定位信息。

### RULE-203：Create 提交后状态正确
- 适用类型：`create / page / footer`
- 触发条件：改动提交接口、保存成功回调、创建后跳转策略。
- 检查方法：提交成功后进入预期状态（详情或列表），新记录可见且可继续操作。
- 常见反模式：
  - 提交后停留原页但无成功反馈。
  - 创建成功但列表/详情无法回查新记录。

### RULE-204：Create 失败提示与禁提交闭环
- 适用类型：`create / page / footer`
- 触发条件：改动错误处理、接口异常分支、按钮禁用逻辑、重复提交防护。
- 检查方法：失败时给出明确错误提示且保留可修正状态，提交按钮禁用/恢复符合预期。
- 常见反模式：
  - 失败无提示或提示不可读，用户无法修正。
  - 提交中未禁用导致重复提交或脏数据。

### RULE-301：Footer 弹层开关稳定
- 适用类型：`footer`
- 触发条件：改动 Footer 入口、弹层容器、遮罩、关闭动作。
- 检查方法：弹层可打开/关闭，关闭后遮罩与焦点状态清理干净。
- 常见反模式：
  - 关闭后残留遮罩阻塞页面。
  - 重复打开导致多层弹层叠加。

### RULE-302：Footer 主链路（列表/详情/创建）可用
- 适用类型：`footer`
- 触发条件：改动 Footer 内列表、详情切换、添加入口、收起行为。
- 检查方法：在弹层内可完成列表到详情切换，创建态可进入并退出到列表态。
- 常见反模式：
  - 详情可进不可退。
  - 创建入口策略不一致（该有时没有，不该有时出现）。

### RULE-303：Drawer 生命周期完整
- 适用类型：`drawer`
- 触发条件：改动抽屉打开条件、关闭动作、遮罩层、焦点管理。
- 检查方法：抽屉可按条件打开并正常关闭，关闭后主页面交互恢复。
- 常见反模式：
  - 抽屉关闭后仍拦截滚动或点击。
  - 多次打开后状态串扰。

### RULE-401：URL 与导航状态同步
- 适用类型：`regression / page`
- 触发条件：改动 `AppNavigationContext`、L1/L2/L3、target 参数、深链逻辑。
- 检查方法：导航切换后 URL 参数与页面状态一致，刷新/复制链接可复现同一状态。
- 常见反模式：
  - URL 变化但页面不变化，或反之。
  - 深链打开后被错误重定向。

### RULE-402：浏览器前进后退回放一致
- 适用类型：`regression`
- 触发条件：改动 history 栈、tab 切换、详情页状态记录。
- 检查方法：执行前进/后退时，页面状态按访问顺序回放且无错位。
- 常见反模式：
  - 后退跳到错误页面。
  - 回放后 L1/L2/target 组合不一致。

### RULE-403：刷新恢复与非法参数兜底
- 适用类型：`regression`
- 触发条件：改动启动初始化、路由解析、参数兜底或持久化恢复逻辑。
- 检查方法：刷新后保持可达状态，非法参数会自动回退到可用默认页。
- 常见反模式：
  - 刷新后进入不可恢复状态。
  - 非法参数触发死循环或白屏。

### RULE-404：权限与角色边界可恢复
- 适用类型：`regression / page`
- 触发条件：改动角色权限、菜单过滤、可见入口、工作空间范围。
- 检查方法：受限入口不会导致崩溃，系统会落到该角色可访问页面并保持可操作。
- 常见反模式：
  - 入口被隐藏但 URL 仍可进入并报错。
  - 权限切换后停留在无权限页面无法恢复。
